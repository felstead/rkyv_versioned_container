# Changelog

This project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.2.0]

First release published to crates.io. This release is not source compatible with 0.1.0, though the
serialized format is unchanged: data written by 0.1.0 still reads, since the type ID and version ID
are derived exactly as before.

### Added

- `VersionedUpgrade`, a new trait for allowing conversion of older serialized data to the newest
  version.
- `MaybeUpgraded`, holding either a borrowed archived value that is already the latest version or an
  owned converted one, with `into_owned()` to produce an owned value from either.
- `upgrade_from_tagged_bytes`, combining `access_from_tagged_bytes` with
  `VersionedUpgrade::upgrade`.
- `VersionedContainer` now contains consts `ARCHIVE_TYPE_NAME` as a `&'static str` and
  `NEWEST_VERSION_ID` as a `u32`, both generated by the derive.
- `#[rkyv_versioned(archive_type_name = "...")]` on a container, pinning the string the type ID is
  hashed from instead of using the container's identifier. This is useful when there are potentially
  two identically named types in different modules, and you want to disambiguate explicitly.
- `RkyvVersionedError::UpgradeNotSupported`, for upgrade arms that deliberately refuse to convert
  older data.
- `Error::source()` on `RkyvVersionedError`, so a wrapped rkyv error appears in error chains.
- Documentation for the buffer contract, the accessor pattern for reading across versions, and the
  full safety contract of `access_from_tagged_bytes_unchecked`.

### Changed

- **Breaking.** `RkyvVersionedError::UnexpectedTypeError` and
  `RkyvVersionedError::UnsupportedVersionError` are now struct variants. Both keep the integers they
  had and add the container's type name, and `UnsupportedVersionError` also reports the newest known
  version, so a message reads `EntryContainer: unsupported version 3 (newest known: 1)` instead of
  two bare integers.
- **Breaking.** `RkyvVersionedError` is `#[non_exhaustive]`, so matches outside this crate need a
  catch-all arm. Adding variants is no longer a breaking change.
- **Breaking.** `VersionedContainer` gained two required constants, which affects manual
  implementors. Types using the derive are unaffected.
- The derive emits fully qualified paths, so it no longer requires `VersionedContainer` and
  `const_crc32` to be in scope at the use site. A plain `use
  rkyv_versioned::VersionedArchiveContainer;` is now enough.
- Both crates moved to edition 2024, with a minimum supported Rust version of 1.85.

### Fixed

- Documentation updates for the buffer contract, the accessor pattern for reading across versions,
  and the full safety contract of `access_from_tagged_bytes_unchecked`.

## [0.1.0]

Initial version, not published to crates.io.

- `VersionedContainer` and `#[derive(VersionedArchiveContainer)]`.
- `to_tagged_bytes`, `to_tagged_bytes_in`, `get_type_and_version_from_tagged_bytes`,
  `access_from_tagged_bytes`, and `access_from_tagged_bytes_unchecked`.
